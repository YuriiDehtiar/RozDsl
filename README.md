# RozDsl — мінімальна DSL для опису розгортання сервісів (.roz → JSON)

Цей репозиторій — навчальний приклад того, як створити **власну мову конфігурацій (DSL)** і реалізувати для неї **мінімальний “компілятор/транслятор”**.

Користувач пише конфігурацію у файлі **`.roz`** (зручний для людини синтаксис), а інструмент перетворює її у **JSON** (зручний для машинної обробки формат).  
Проєкт побудований так, щоб показати типову архітектуру компілятора: **Lexer → Parser → AST → Validation → CodeGen**.

---

## Що тут є

### 1) `Roz.Language` (Class Library, .NET 8)
“Движок мови” — уся логіка DSL:
- **Lexer**: розбиває текст на токени (ключові слова, рядки, числа, дужки тощо)
- **Parser**: будує **AST** (дерево/модель програми) з токенів
- **Diagnostics**: збір помилок з позиціями (`TextSpan`, `Diagnostic`, `DiagnosticBag`)
- **Semantic validation**: доменні перевірки правил
- **JSON generation**: формування вихідного JSON

Публічний вхід для зовнішнього коду — `RozCompiler`, який запускає весь конвеєр і повертає `CompilationResult`.

### 2) `Roz.Cli` (Console App, .NET 8)
Консольна утиліта, яка:
- приймає шлях до `.roz` файлу
- викликає `RozCompiler`
- якщо є помилки — друкує їх
- якщо все добре — записує JSON у файл

---

## Чому це “власна мова”, а не просто програма на C#
**Мова** — це формат `.roz` з власним синтаксисом і правилами.  
**C#** — лише інструмент, яким ми реалізували компілятор цієї мови.

## Синтаксис `.roz` (версія v1)

Приклад `demo.roz`:

```roz
service api {
  image "my-api:1.0"
  replicas 2
  port 8080:80
}

service web {
  image "nginx:latest"
  replicas 1
  port 8081:80
}


Правила (v1)
- Файл складається з блоків `service`
- Формат: `service <name> { ... }`
- Всередині блоку підтримуються поля:
  - `image "<...>"` — обов’язково
  - `replicas <number>` — обов’язково, має бути > 0
  - `port <host>:<container>` — може повторюватися (0+ разів)
- Назви сервісів мають бути унікальні
- Порти мають бути в діапазоні 1..65535


Вихідний JSON
- Результат компіляції — JSON такого виду:
  - `services[]`
    - `name`
    - `image`
    - `replicas`
    - `ports[]` (масив об’єктів `{ host, container }`)


Як запустити
Варіант 1: через dotnet run
1) Перейди в папку `Roz.Cli`
2) Запусти:
   dotnet run -- Samples/demo.roz
Опційно можна вказати шлях до вихідного файлу:
   dotnet run -- Samples/demo.roz out.json
Варіант 2: через Visual Studio (F5)
1) У профілі запуску `Roz.Cli` задай Command line arguments, наприклад:
   Samples\demo.roz
2) Запусти проєкт (F5)

Примітка:
- Якщо CLI запустити без аргументів, він покаже help і завершиться з кодом 1 — це очікувано.

Поточний стан і наступні кроки

Реалізовано
- Повний конвеєр `.roz → tokens → AST → validation → JSON`
- Базові доменні перевірки
- Діагностики (повідомлення + `TextSpan`)
- CLI для запуску компіляції

Планується
- Винести генерацію JSON повністю у `CodeGen/JsonGenerator`
- Підтримка редактора у Visual Studio:
  - VSIX пакет
  - TextMate grammar (підсвічування синтаксису)
  - Language Configuration (коментарі/дужки/автозакриття)
- (Рівень “next”) LSP для семантичних підказок і діагностик прямо в редакторі
